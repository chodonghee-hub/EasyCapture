# 캡처 펄스 효과 완료 문서 (front)

> 작업번호 03 · 캡처 확정 시 "펄스 + 시계 방향 빛" 효과 구현 결과 요약

## 변경 파일

- `src/EasyCapture.App/CaptureOverlayWindow.xaml`: 효과용 `PulseRing`(링)과 `Sweep`(빛 컨테이너) 추가, 평소엔 숨김.
- `src/EasyCapture.App/CaptureOverlayWindow.xaml.cs`: `PlayConfirmEffect`로 효과 재생, 확정 후 입력 무시, 효과 상수 모음.
- `src/EasyCapture.App/CaptureService.cs`: `OnConfirmed`가 PNG를 만든 뒤 효과를 재생하고, 끝나면 닫기·저장·알림.

## 동작 방식

- 순서: Enter 확정 → PNG 인코딩 → 효과 → 오버레이 닫기 → 보관소 저장 → 알림.
- 테두리: 두께 3배·밝은 하늘색으로 120ms 커졌다가 120ms에 원래대로 복귀(AutoReverse, CubicEase).
- 링: 같은 모양 테두리가 350ms 동안 사방 14px 퍼지며 투명해짐(CubicEase Out, 불투명도는 QuadraticEase In).
- 빛: 12시 방향에서 출발해 600ms에 한 바퀴, 길이는 둘레의 25%, 8조각의 불투명도를 낮춰 꼬리를 표현(QuadraticEase InOut, 시작·끝 15% 구간 페이드).
- 방향: 경로를 상단 중앙→우상→우하→좌하→좌상 순서로 만들고 `StrokeDashOffset`을 줄여 시계 방향으로 이동(화면 밖 렌더로 확인).
- 상수(길이·퍼짐·빛 길이·조각 수·색)는 `CaptureOverlayWindow` 상단에 모아 두었다.

## 안전 장치

- PNG는 오버레이가 뜨기 전에 찍어 둔 정지 이미지에서 효과 시작 전에 잘라 만들므로 효과가 섞이지 않는다.
- 확정 후(`_finished`) 키·마우스 입력을 모두 무시해 이중 확정, 프리셋 저장, Esc 취소가 불가능하다.
- 포커스를 잃어도 취소 경로가 `_finished`로 막혀 저장은 유지된다.
- 완료 처리는 애니메이션 완료·안전망 타이머(900ms)·창 닫힘 중 먼저 온 한 번만 실행하고, 이미 닫힌 뒤 호출돼도 예외가 없다.
- 효과 중에는 `_overlay`를 유지해 새 캡처가 효과 화면을 찍지 않는다.
- Windows 애니메이션이 꺼져 있으면(`ClientAreaAnimation=false`) 효과 없이 즉시 닫는다. 취소 경로에는 효과가 없다.

## 검증 결과

- Release 빌드: 경고 0, 오류 0.
- 하니스 시험(창을 띄우지 않음): 확정 1회·완료 1회, 이중 확정 무시, 100ms에 창을 닫아도 완료 1회, 완료 안에서 닫아도 예외 없음, 1×1 영역 예외 없음.
- 빛 방향 시험(화면 밖 렌더): offset 0은 상단 중앙 오른쪽, 음수는 시계 방향, 양수는 반대 방향임을 확인.

## 확인하지 못한 것

- 실제 화면에서의 모양·타이밍(오버레이를 띄우는 시험은 하지 않음), 효과 완료 이벤트가 실제 창에서 정상 발생하는지.
- 이 PC는 `ClientAreaAnimation=False`라 효과가 생략되는 경로만 실환경에서 해당된다.
- 새 exe 5초 실행 확인(이미 실행 중인 EasyCapture.exe 때문에 불가), 멀티모니터·혼합 DPI, 화면 가장자리에서 링 일부가 잘리는지.
- 실제 창에서 `Storyboard.Completed` 발생(안전망 타이머가 900ms에 완료를 보장).
