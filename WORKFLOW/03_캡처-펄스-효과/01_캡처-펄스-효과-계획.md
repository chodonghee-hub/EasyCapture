# 캡처 펄스 효과 작업 계획

> 작업번호 03 · 캡처 확정 시 선택 영역 테두리에 "펄스 + 시계 방향 빛" 효과를 한 번 보여주는 계획

## 최초 접수 시간

2026-11-02

## 문제 정의

- Enter로 캡처를 확정하면 오버레이가 즉시 닫혀 확정됐다는 시각 피드백이 없다.
- 효과는 저장 PNG에 섞이면 안 되고, 확정 후 입력·취소·포커스 상실에도 캡처가 안전하게 저장돼야 한다.

## 작업 계획

- 확정 시 테두리 효과 1회: 펄스(테두리 두꺼워짐·밝아짐 + 바깥으로 퍼지는 링)와 시계 방향으로 도는 빛줄기를 동시에 재생한다.
- 순서는 PNG 인코딩 → 효과 → 오버레이 닫기 → 저장·알림으로 한다.
- 효과 중에는 키·마우스 입력을 모두 무시하고, 창이 먼저 닫혀도 저장은 한 번 보장한다.
- Windows 애니메이션이 꺼져 있으면 효과 없이 기존처럼 즉시 닫는다.
- 효과 상수(길이·퍼짐 거리·빛 길이·색)는 한 곳에 모으고, 설정 옵션과 Core 변경은 넣지 않는다.

## 작업 기대 효과

- 확정 순간이 눈에 보여 캡처됐다는 확신을 준다.
- 지연은 효과 길이(약 0.6초)만큼만 늘고, 저장 결과는 이전과 동일하다.

## 작업 결과

- 구현 완료(최종 효과): 확정 시 600ms 동안 ①테두리 두께 3배·밝은 하늘색 반응(120ms 왕복) ②링이 사방 14px 퍼지며 투명해짐(350ms) ③12시에서 출발한 빛(둘레 25%, 꼬리 그라데이션)이 시계 방향으로 한 바퀴.
- 동작 규칙: 효과 중 입력은 모두 무시, 확정된 캡처는 취소 불가, PNG는 효과 시작 전에 정지 비트맵에서 인코딩, 애니메이션 비활성(ClientAreaAnimation=false)이면 효과 생략.
- 변경 파일: `CaptureOverlayWindow.xaml`, `CaptureOverlayWindow.xaml.cs`, `CaptureService.cs`.
- 검증: Release 빌드 경고·오류 0, 입력 무시·이중 확정 방지·창 먼저 닫힘·1×1 영역 시험(화면에 띄우지 않는 하니스) 통과, 빛 방향(시계 방향)은 화면 밖 렌더로 확인.
- 독립 검증(별도 에이전트): Release 빌드 경고 0·오류 0, `dotnet test` 393개 전부 통과, 높음·중간 문제 없음.
- 독립 검증 낮음 4건: 효과 600ms 중 새 캡처 요청 무시, 일부 효과 수치가 상수 블록 밖 리터럴, 효과 중 Alt+F4 차단(의도), 종료 중 해제된 트레이로 알림(예외 없음 확인).
- 확인하지 못한 것: 실제 화면에서의 모양·타이밍(키·마우스 주입 금지로 오버레이를 띄워 보지 못함), 실제 창에서 Storyboard.Completed 발생(안전망 타이머가 900ms에 보장), 멀티모니터·혼합 DPI, 화면 가장자리에서 링 일부가 잘림, 실행 중인 EasyCapture.exe가 있어 새 exe 5초 실행 확인 불가.

- 사용자 결정 대기: "애니메이션 설정과 무관하게 항상 재생할지"(기본: 설정 존중 유지).
