# 캡처 도구 작업 계획

> 작업번호 01 · Windows용 개인 캡처 도구 "EasyCapture"(가칭) 제작 계획

## 최초 접수 시간

2026-10-23 00:25

## 문제 정의

- 일반 캡처 도구는 매번 영역을 직접 드래그해야 해서 같은 영역을 반복 캡처하기 번거롭다.
- 캡처한 이미지를 모아 두고 파일처럼 복사·붙여넣기 할 수단이 없다.
- 단축키가 고정되어 있어 사용자가 원하는 키로 바꿀 수 없다.
- 설치 파일(Setup.exe)로 쉽게 배포·설치할 수 있어야 한다.

## 작업 계획

### 목표 요약

- 단축키 → 미리 지정한 영역 표시 → Enter로 캡처 → 목록에 보관 → 파일처럼 복사·붙여넣기.
- 단축키는 모두 사용자가 자유롭게 변경한다.
- Setup.exe 하나로 설치한다.

### 기술 스택

- 환경: .NET 9 SDK(9.0.311), Node 24, winget, Windows SDK (Inno Setup/WiX는 없음 → M8에서 winget `JRSoftware.InnoSetup`으로 설치).
- 앱: C# .NET 9 + WPF (`net9.0-windows`, 트레이용 WinForms `NotifyIcon` 허용), PerMonitorV2 DPI `app.manifest` 필수.
- 구조: `src/EasyCapture.App`(화면), `src/EasyCapture.Core`(UI 무관 로직), `tests/EasyCapture.Tests`(xUnit), `installer/`(Inno Setup).
- 전역 단축키: Win32 `RegisterHotKey` + 숨은 메시지 창.

### 핵심 설계

| 항목 | 내용 |
|---|---|
| 단축키 동작 | 캡처 시작(프리셋별 지정 가능) / 클립보드 패널 열기 / 마지막 캡처 다시 복사 |
| 기본 단축키(제안) | 캡처 Ctrl+Shift+S, 패널 Ctrl+Shift+V (모두 변경 가능) |
| 캡처 흐름 | 단축키 → 가상 화면 전체 정지 캡처(멀티모니터/DPI 대응) → 어두운 오버레이에 프리셋 영역 밝게 표시 |
| 오버레이 조작 | Enter 캡처, Esc 취소, 방향키/드래그로 이동·크기 조절, Tab 프리셋 전환, R 새 영역 지정 후 저장 |
| 프리셋 | 이름, 모니터 기준 좌표/크기, 전용 단축키(선택) |
| 설정 저장 | `%APPDATA%\EasyCapture\settings.json` |
| 캡처 보관소 | `%LOCALAPPDATA%\EasyCapture\captures\*.png` + 인덱스(JSON), 개수/기간 제한, 고정(핀), 이름 변경, 삭제 |
| 클립보드 패널 | 단축키 팝업, 썸네일 그리드(최신순), 키보드만으로 조작, 다중 선택(Ctrl/Shift) |
| 복사 방식 | Ctrl+C/Enter → CF_HDROP 파일 복사, 설정에서 '파일+이미지(기본)/파일만/이미지만' 선택 |
| 붙여넣기 | 외부 앱으로 드래그 앤 드롭, 이전 활성 창에 Ctrl+V 전송 |
| 자동 복사 | 캡처 직후 최신 캡처를 시스템 클립보드에 자동 복사(기본 켜짐) |
| 트레이 | 메뉴(캡처, 패널, 설정, 종료), Mutex 중복 실행 방지, HKCU Run 자동 시작 옵션 |
| 설치 파일 | `dotnet publish -r win-x64 --self-contained` → Inno Setup, `PrivilegesRequired=lowest`, 바로가기/자동 시작 선택, 제거 시 데이터 삭제 확인 |
| 산출물 | `installer/output/EasyCapture-Setup-{버전}.exe` |

### 진행 규칙

1. 메인은 도구를 쓰지 않고 모든 작업을 서브에이전트에게 위임한다.
2. 구현은 Sonnet이, 검증은 작성자와 다른 서브에이전트가 맡는다.
3. 임무마다 Codex(gpt-6-astra, 읽기 전용) 임무 단위 검토(bug/side-effect/overheading) 후 다음 임무로 넘어가고, 전체 완료 시 Codex 최종 점검을 한다.
4. 검증된 높음·중간 지적만 수정하고, 재검토는 최대 2회까지 한다.
5. 완료 시 이 문서의 '작업 결과' 갱신, front/back 완료 문서(`01_front-캡처-도구.md`, `01_back-캡처-도구.md`) 작성, `00_INDEX.md` 링크 갱신을 모두 수행한다.
6. 퍼블리싱(HTML/CSS) 작업은 없고, WPF XAML은 일반 구현 담당(Sonnet)이 맡는다.
7. git 초기화/커밋은 사용자 확인 후에 한다.
8. 임무는 순서대로 하나씩 완료+검토한 뒤 다음으로 진행한다.
