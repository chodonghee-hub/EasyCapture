# 실행 배치파일 작업 계획

> 작업번호 02 · 더블클릭으로 빌드 후 바로 실행하는 `run.bat` 제작 계획

## 최초 접수 시간

2026-11-01

## 문제 정의

- 앱을 실행하려면 매번 빌드 명령과 exe 경로를 직접 입력해야 해서 번거롭다.
- 트레이 앱이라 실행해도 창이 없어 제대로 떴는지 알기 어렵다.

## 작업 계획

- 프로젝트 루트에 `run.bat` 하나를 만든다.
- 어디서 실행해도 프로젝트 루트로 이동한 뒤 동작한다.
- `dotnet` 확인 → Release 빌드 → `EasyCapture.exe`를 분리 실행하고 배치는 종료한다.
- 실패 시 안내 메시지와 `pause` 후 종료 코드 1로 끝낸다.
- 파일은 ASCII·CRLF로 작성해 코드페이지 문제를 피한다.

## 작업 대상 파일

작업 폴더(프로젝트 루트): `프로젝트 루트(easy_capture 폴더)`

### back (실행·빌드 영역)

- `run.bat` (신규)
- 완료 문서: `WORKFLOW/02_실행-배치파일/back/02_back-실행-배치파일.md`

### front (화면 영역)

- 변경 없음

## 작업 기대 효과

- 더블클릭 한 번으로 최신 소스를 빌드하고 앱을 실행한다.
- 실패 원인이 화면에 남아 바로 확인할 수 있다.

## 작업 결과

- `run.bat` 작성 완료 (ASCII, CRLF, 한글 경로 대응).
- 검증: 프로젝트 폴더·`C:\` 두 위치에서 실행해 종료코드 0, 5초 뒤 프로세스 생존, 종료 후 잔여 0개 확인.
- 미확인: 빌드 실패·dotnet 없음·exe 없음 경로, 트레이 아이콘 시각 확인.

## 개선 작업 (2026-11-02)

- 배경: 실행 중인 EasyCapture가 빌드 출력 파일을 잠가 빌드가 실패하고, SingleInstance 때문에 구 인스턴스가 있으면 새 빌드가 적용되지 않는다.
- 계획: 빌드 전에 실행 중인 EasyCapture.exe를 종료하고, 시작 후 생존 여부를 경고로 알린다.
- 결과: 빌드 전 종료 단계와 시작 후 생존 확인(경고만, 종료코드 불변) 추가 완료.
- 검증: 미실행 상태 실행 성공, 실행 중 재실행 시 종료 후 새 PID로 빌드·실행 성공(2026-11-02 22:31 기준), 시험 후 잔여 0개.
- 미확인: 종료 실패(권한) 경로, 한글이 아닌 로케일에서의 tasklist 동작.
